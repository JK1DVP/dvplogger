# DVPlogger OTRSP/TCP アンテナ制御プロトコル

**状態:** DVPlogger 実装仕様\
**トランスポート:** TCP\
**デフォルト TCP ポート:** `12001`\
**行終端:** Carriage Return (`CR`, `0x0D`)

## 1. 目的

本書は、DVPlogger と外部アンテナスイッチコントローラ間で使用する
OTRSP/TCP
プロトコル、およびアンテナのメタデータと無線機の運用情報を交換するための
DVPlogger 独自拡張について記述します。

設計上の目的は次の2点です。

1.  現在 DVPlogger で使用している標準 OTRSP
    のアンテナ制御方式との互換性を維持する。
2.  拡張対応アンテナサーバーとの間でアンテナ名を交換し、無線機の周波数・モード情報を送信できるようにする。これにより、GUI表示、自動アンテナチューナー、フィルター、その他の局設備から利用できるようにする。

標準のアンテナ選択コマンドは、これらの拡張とは独立して維持します。

------------------------------------------------------------------------

## 2. 構成と情報の管理主体

DVPlogger がクライアントとして動作し、アンテナコントローラ／サーバーが
TCP 接続を受け付けます。

  ------------------------------------------------------------------------------------
  情報                                管理主体
  ----------------------------------- ------------------------------------------------
  無線機の運用周波数                  DVPlogger

  無線機の運用モード                  DVPlogger

  バンドごとのアンテナ優先順位        DVPlogger

  要求するアンテナ割り当て            DVPlogger

  物理アンテナの番号と名称            アンテナサーバー

  実際のアンテナ切替ハードウェア      アンテナサーバー

  ホットスイッチ防止                  現在は DVPlogger が TX/RX
                                      シーケンスを実施。ハードウェア側での保護も推奨
  ------------------------------------------------------------------------------------

DVPlogger
は、バンドごとのアンテナ優先順位テーブルからアンテナ割り当てを決定します。割り当てを変更する前に、すべての有効な無線機が
RX 状態であることを確認し、さらに現在 150 ms
の安定待ち時間を設けた後、OTRSP コマンドを送信します。

------------------------------------------------------------------------

# 第I部 --- DVPlogger が使用する標準 OTRSP コマンド

## 3. AUX アンテナ選択コマンド

DVPlogger は OTRSP の AUX
機構を使用して、要求するアンテナ番号を通知します。

### 3.1 AUX1

``` text
AUX1 <antenna-number>
```

現在の DVPlogger 実装では、

``` text
AUX1 = Radio 0 のアンテナ選択
```

です。

例:

``` text
AUX1 2
```

は、Radio 0 にアンテナ2を要求します。

### 3.2 AUX2

``` text
AUX2 <antenna-number>
```

現在の DVPlogger 実装では、

``` text
AUX2 = Radio 1 のアンテナ選択
```

です。

例:

``` text
AUX2 7
```

は、Radio 1 にアンテナ7を要求します。

### 3.3 アンテナ番号 0

DVPlogger は、使用可能なアンテナが割り当てられていない場合、

``` text
AUX1 0
```

または、

``` text
AUX2 0
```

を送信する場合があります。

アンテナ0の物理的な意味は実装依存ですが、アンテナサーバー側では通常「アンテナなし／無効」として扱うことを想定します。ただし、ハードウェアが別の安全状態への割り当てを必要とする場合はその限りではありません。

### 3.4 割り当て例

``` text
AUX1 2
AUX2 1
```

は、

``` text
Radio 0 -> Antenna 2
Radio 1 -> Antenna 1
```

を意味します。

標準 AUX
コマンドで通知されるのはアンテナ番号だけです。アンテナ名、無線機の周波数、運用バンド、運用モード、あるいはそのアンテナが選択された理由は通知されません。

------------------------------------------------------------------------

## 4. DVPlogger のアンテナ切替シーケンス

DVPlogger
は、各無線機のバンドとアンテナ優先順位テーブルから、使用するアンテナを計算します。

割り当て変更が必要な場合の処理は次のとおりです。

``` text
要求するアンテナ割り当てを計算
        |
        v
有効な無線機のいずれかが送信中か？
        |
   yes  |----> 待機
        |
       no
        |
        v
全無線機が RX になってから 150 ms 待機
        |
        v
AUX1 / AUX2 を送信
        |
        v
新しい割り当てを有効状態として記録
```

これにより、DVPlogger
が意図的に送信中のアンテナマトリクスを切り替えることを防止します。

ただし、アンテナサーバー／スイッチ側にも、必要に応じて独立したハードウェアインターロックを実装することを推奨します。

------------------------------------------------------------------------

# 第II部 --- DVPlogger OTRSP 拡張

## 5. 設計方針

拡張機能は、標準の `AUX1` / `AUX2`
切替コマンドを変更せず、追加のメタデータを提供します。

現在定義する拡張コマンドは次のとおりです。

``` text
?ANTLIST
ANTNAME <n> <name>
ANTLIST END

RADIO0 FREQ <frequency-hz>
RADIO0 MODE <mode>

RADIO1 FREQ <frequency-hz>
RADIO1 MODE <mode>
```

情報の流れは大きく2種類に分かれます。

``` text
アンテナサーバー -> DVPlogger
    アンテナ名

DVPlogger -> アンテナサーバー
    無線機の周波数
    無線機のモード
    アンテナ選択（標準 AUX）
```

------------------------------------------------------------------------

## 6. 拡張機能のネゴシエーション

DVPlogger は、すべての OTRSP 機器に対して直ちに `RADIOx`
拡張コマンドを送ることはしません。

TCP 接続確立後、DVPlogger は、

``` text
?ANTLIST
```

を送信します。

拡張対応サーバーは、0個以上の `ANTNAME` レコードを返し、最後に、

``` text
ANTLIST END
```

を返します。

例:

``` text
DVPlogger -> ?ANTLIST

Server -> ANTNAME 1 40m Dipole
Server -> ANTNAME 2 Tribander
Server -> ANTNAME 3 50MHz 2el
Server -> ANTNAME 4 144/430/1200 GP
Server -> ANTNAME 5 2.4GHz antenna
Server -> ANTNAME 6 5.6GHz antenna
Server -> ANTNAME 7 Second triband DP
Server -> ANTNAME 8 Antenna 8
Server -> ANTNAME 9 Antenna 9
Server -> ANTLIST END
```

DVPlogger は、

``` text
ANTLIST END
```

を受信すると、その接続先が DVPlogger OTRSP
拡張に対応していると判断します。

その後にのみ、DVPlogger は `RADIOx FREQ` および `RADIOx MODE`
のメタデータ送信を開始します。

この拡張に対応しない標準 OTRSP 機器は `?ANTLIST`
を無視できます。その場合も DVPlogger は標準 AUX
によるアンテナ選択を継続し、`RADIOx` 拡張情報は送信しません。

------------------------------------------------------------------------

## 7. ANTNAME

### 7.1 書式

``` text
ANTNAME <antenna-number> <antenna-name>
```

例:

``` text
ANTNAME 2 Tribander
```

アンテナ番号は、

``` text
AUX1 2
AUX2 2
```

で使用する物理アンテナ番号と同一です。

### 7.2 情報の管理主体

物理的なアンテナ設備を表すのはアンテナサーバーであるため、**アンテナサーバーをアンテナ名の管理主体（master）**とします。

DVPlogger
側にもローカル／デフォルトのアンテナ名をフォールバック用として保持できますが、拡張対応サーバーから受信した名称は、DVPlogger
の実行時アンテナ名称テーブルを更新するために使用します。

### 7.3 空白を含むアンテナ名

アンテナ番号より後ろの文字列全体をアンテナ名として扱います。

したがって、

``` text
ANTNAME 7 Second triband DP
```

は、

``` text
antenna-number = 7
antenna-name   = Second triband DP
```

を意味します。

------------------------------------------------------------------------

## 8. ANTLIST END

### 8.1 書式

``` text
ANTLIST END
```

`?ANTLIST` に対する応答の終了を示します。

現在の実装では、同時に拡張機能への対応を示す capability indication
としても使用します。

これを受信した後、DVPlogger は以下に示す `RADIOx`
メタデータを送信できます。

------------------------------------------------------------------------

# 第III部 --- Radio メタデータ拡張

## 9. RADIOx FREQ

### 9.1 書式

``` text
RADIO<radio-number> FREQ <frequency-hz>
```

現在定義する radio number は、

``` text
RADIO0
RADIO1
```

です。

例:

``` text
RADIO0 FREQ 14025000
RADIO1 FREQ 7025000
```

周波数は **Hz 単位の整数値**です。

したがって、

``` text
14025000 = 14.025000 MHz
7025000  = 7.025000 MHz
```

となります。

バンド番号だけではなく絶対周波数を Hz
単位で通知するのは、以下のような機器から利用できるようにするためです。

-   自動アンテナチューナー
-   自動バンドパス／ローパスフィルター
-   アンプ／フィルターコントローラ
-   アンテナ選択表示装置
-   その他の局設備自動化システム

受信側は、この周波数から必要に応じて独自にバンドを判定できます。

### 9.2 更新動作

DVPlogger
は拡張機能のネゴシエーション完了後に現在周波数を送信し、その後は周波数が変化した場合に送信します。

CAT polling
のたびに変化していない周波数を繰り返し送信することは想定していません。

------------------------------------------------------------------------

## 10. RADIOx MODE

### 10.1 書式

``` text
RADIO<radio-number> MODE <mode>
```

例:

``` text
RADIO0 MODE CW
RADIO1 MODE USB
```

mode には DVPlogger の運用モード表現を使用します。

代表的な値として以下があります。

``` text
LSB
USB
CW
CW-R
RTTY
RTTY-R
AM
FM
WFM
DV
```

受信側は、未知のモード文字列を受信しても処理を継続できるようにすることを推奨します。

### 10.2 更新動作

周波数と同様に、DVPlogger
は拡張ネゴシエーション完了後に現在モードを送信し、その後はモードが変化した場合に送信します。

------------------------------------------------------------------------

# 第IV部 --- 組み合わせた動作

## 11. 接続時の例

拡張対応サーバーとの典型的な接続は次のようになります。

``` text
TCP connection established

DVPlogger -> ?ANTLIST

Server -> ANTNAME 1 40m Dipole
Server -> ANTNAME 2 Tribander
Server -> ANTNAME 3 50MHz 2el
Server -> ANTLIST END

DVPlogger -> RADIO0 FREQ 14025000
DVPlogger -> RADIO0 MODE CW
DVPlogger -> RADIO1 FREQ 7025000
DVPlogger -> RADIO1 MODE CW

DVPlogger -> AUX1 2
DVPlogger -> AUX2 1
```

この時点でサーバー側は、局の状態を例えば次のように解釈できます。

``` text
Radio 0
  14.025000 MHz
  CW
  |
  +--> Antenna 2 "Tribander"

Radio 1
   7.025000 MHz
  CW
  |
  +--> Antenna 1 "40m Dipole"
```

------------------------------------------------------------------------

## 12. アンテナを変更しない周波数変更

Radio 0 が、

``` text
14.025000 MHz CW
```

から、

``` text
14.035000 MHz CW
```

へ移動し、使用アンテナが変わらない場合、DVPlogger
が送信する必要があるのは、

``` text
RADIO0 FREQ 14035000
```

だけです。

アンテナ割り当てそのものが変化しなければ、新しい AUX
コマンドは不要です。

これは特に自動アンテナチューナーにとって重要です。アンテナスイッチ位置が変わらなくても、チューナーは正確な運用周波数を必要とする可能性があります。

------------------------------------------------------------------------

## 13. アンテナ変更を伴うバンド変更

Radio 0 が 7 MHz から 14 MHz へ移動し、DVPlogger
がアンテナ1からアンテナ2へ変更する必要があると判断した場合、メタデータは例えば、

``` text
RADIO0 FREQ 14025000
RADIO0 MODE CW
```

となります。

その後、DVPlogger の RX／ホットスイッチ防止シーケンスを経て、

``` text
AUX1 2
```

を送信します。

これによりサーバー側は、

-   無線機の運用状態
-   実際に要求されたアンテナスイッチ位置

を別々の情報として扱えます。

------------------------------------------------------------------------

## 14. モード変更

周波数を変更せずにモードだけが変化した場合は、

``` text
RADIO0 MODE USB
```

だけで十分です。

アンテナ割り当てが必ずしも変化するわけではありませんが、この情報は他の局設備から利用できます。

------------------------------------------------------------------------

# 第V部 --- サーバー側の動作

## 15. 最小限の標準互換サーバー

アンテナ切替機能だけを実装するサーバーは、以下だけを理解すれば動作できます。

``` text
AUX1 <n>
AUX2 <n>
```

以下は無視して構いません。

``` text
?ANTLIST
```

また、未知の拡張コマンドも無視できます。

このようなサーバーでも DVPlogger から使用できます。

------------------------------------------------------------------------

## 16. 拡張対応サーバー

拡張対応サーバーは、以下を実装することを想定します。

1.  `?ANTLIST` を受信する。
2.  アンテナ定義を `ANTNAME` レコードとして返す。
3.  `ANTLIST END` で一覧を終了する。
4.  `RADIO0/1 FREQ` を受信する。
5.  `RADIO0/1 MODE` を受信する。
6.  標準の `AUX1/AUX2` を引き続き受信する。
7.  各無線機と現在選択されているアンテナとの対応を保持する。

これによりGUIでは、例えば以下のような表示ができます。

``` text
Radio 0
14.025000 MHz  CW
        |
        +----> ANT 2
               Tribander

Radio 1
 7.025000 MHz  CW
        |
        +----> ANT 1
               40m Dipole
```

------------------------------------------------------------------------

## 17. アンテナ名の永続化

アンテナサーバーを物理アンテナ定義の管理主体とするため、拡張対応サーバーでは通常、アンテナ名をローカルに保存することを想定します。

例えば、

``` json
{
  "antenna_names": {
    "1": "40m Dipole",
    "2": "Tribander",
    "3": "50MHz 2el"
  }
}
```

のように保存できます。

この保存形式自体は実装依存であり、通信プロトコルの一部ではありません。

------------------------------------------------------------------------

# 第VI部 --- 互換性と実装上の注意

## 18. 後方互換性

アンテナ切替そのものは従来どおり、

``` text
AUX1
AUX2
```

を使用します。

DVPlogger は、

``` text
?ANTLIST
```

で拡張対応の有無を調べます。

サーバーが、

``` text
ANTLIST END
```

まで応答しなければ、DVPlogger は `RADIOx FREQ/MODE`
の送信を有効にしません。

したがって、拡張対応版 DVPlogger は従来の OTRSP
アンテナコントローラとも引き続き使用できます。

------------------------------------------------------------------------

## 19. 未知のコマンド

相互運用性を確保するため、未対応コマンドを受信した場合は TCP
接続を切断せず、無視することを推奨します。

これは特に、

``` text
?ANTLIST
```

を受信した標準 OTRSP 機器や、将来さらに新しい DVPlogger
メタデータコマンドを受信する拡張対応機器で重要です。

------------------------------------------------------------------------

## 20. 再接続

TCP 再接続後は、拡張対応状態をいったん未知として扱います。

DVPlogger は再度、

``` text
?ANTLIST
```

を送信し、

``` text
ANTLIST END
```

を受信してから `RADIOx` メタデータの送信を再開します。

ネゴシエーション成功後は、現在の周波数とモードを再送し、サーバーが以前の
TCP セッションの情報に依存せず、現在状態を再構築できるようにします。

アンテナ割り当ても、同期が必要な場合には既存の DVPlogger
アンテナ制御ロジックによって再送されます。

------------------------------------------------------------------------

# 第VII部 --- コマンド一覧

## 21. 現在使用する標準 OTRSP コマンド

  方向                 コマンド     用途
  -------------------- ------------ --------------------------
  DVPlogger → Server   `AUX1 <n>`   Radio 0 のアンテナを選択
  DVPlogger → Server   `AUX2 <n>`   Radio 1 のアンテナを選択

## 22. DVPlogger 拡張コマンド

  方向                 コマンド               用途
  -------------------- ---------------------- --------------------------------
  DVPlogger → Server   `?ANTLIST`             アンテナ定義要求／拡張対応確認
  Server → DVPlogger   `ANTNAME <n> <name>`   物理アンテナ名を定義
  Server → DVPlogger   `ANTLIST END`          アンテナ一覧終了／拡張対応通知
  DVPlogger → Server   `RADIO0 FREQ <Hz>`     Radio 0 の運用周波数
  DVPlogger → Server   `RADIO1 FREQ <Hz>`     Radio 1 の運用周波数
  DVPlogger → Server   `RADIO0 MODE <mode>`   Radio 0 の運用モード
  DVPlogger → Server   `RADIO1 MODE <mode>`   Radio 1 の運用モード

------------------------------------------------------------------------

# 第VIII部 --- 将来拡張

## 23. 将来追加可能な情報

現在の書式は、将来さらに局設備制御用のメタデータを追加できるようにしています。

例えば、

``` text
RADIO0 PTT RX
RADIO0 PTT TX

RADIO0 BAND 14
RADIO0 POWER 100

ANTSTATUS 2 OK
TUNER0 STATE TUNED
```

などが考えられます。

ただし、これらは**現時点のプロトコルでは未定義**であり、実装されているものとして扱ってはいけません。

特に、アンテナサーバー上でバンドを表示するだけであれば、

``` text
RADIOx FREQ <Hz>
```

から受信側がバンドを判定できるため、`BAND`
情報を別途追加する必要はありません。

周波数を無線機状態の基本情報とすることで、自動アンテナチューナーなど周波数依存の局設備にも同じ拡張を利用できます。

------------------------------------------------------------------------

## 24. まとめ

本プロトコルでは、以下の3種類の情報を明確に分離します。

``` text
物理アンテナの識別情報
    -> アンテナサーバーが管理
    -> ANTNAME

無線機の運用状態
    -> DVPlogger が管理
    -> RADIOx FREQ / MODE

アンテナ切替要求
    -> DVPlogger が決定
    -> 標準 OTRSP AUX1 / AUX2
```

この構成により、現在使用している OTRSP
アンテナスイッチ実装を維持したまま、DVPlogger
と対応機器の双方が拡張に対応している場合には、より詳細な局情報を交換できます。
